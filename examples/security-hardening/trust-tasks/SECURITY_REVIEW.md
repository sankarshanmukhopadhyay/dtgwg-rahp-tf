## Overall assessment

The framework has a comparatively strong security architecture: audience binding, transport/in-band identity cross-checks, explicit ceremony non-authority, content-pinned definitions, receipt truncation defenses, parser/schema DoS recognition, and a thoughtful delegated-consent design. The main hardening gap is that several high-value protections remain profile-, governance-, or SHOULD-level at exactly the points where destructive or authority-bearing execution becomes irreversible.

## Security controls already present

- Proof-carrying non-bearer documents require an in-band recipient, preventing cross-recipient replay.
- In-band and transport-derived identities must agree when both are present.
- Ceremony membership and receipts explicitly confer no authority.
- Ceremony definitions are content-pinned and receipts defend against truncation.
- Delegated-consent design binds exact payload/type, rechecks policy, pins state and uses single-use grants.
- Parser and dynamic-schema DoS are explicitly recognized.

**Verification / closure evidence**

- Restart/reconnect tests show replay memory survives for the task-defined relevance window.

- A document is later forwarded, retained, transformed, or relied on outside that transport session.

**Evidence**

**Preconditions**

- Authorization policy is keyed to identifier strings or resolver output.

**Evidence**

| Source | Observation |
|---|---|
| `SPEC.md#2-terminology` | VID may be a DID, X.509 subject, OIDC subject, key thumbprint, or other identifier accepted by the consumer trust framework. |
