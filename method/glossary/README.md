# RAHP glossary

This glossary explains RAHP terms in simple English. The YAML files in `terms/` are the authoritative source. Generated pages and bundles must be rebuilt from these files.

## Writing rules

1. Prefer a short sentence over formal language.
2. Use common words when they are accurate.
3. Define one idea at a time.
4. Add a plain example when it helps.
5. Say what a term must not be confused with when the distinction matters.
6. Reuse an external definition when RAHP does not need its own meaning.

The glossary is explanatory. Normative requirements remain in the method, catalogue, schemas and deployment artefacts.

## Operating model

The source/generated separation is intentionally similar to the governance-executable approach used by `sankarshanmukhopadhyay/ctwg-main-glossary`: structured term records are authoritative, schemas validate them, and human/machine views are generated. RAHP keeps only terms needed to understand or operate RAHP; it does not copy the larger glossary wholesale.
