# v0.6.0 — Portable toolkit identity and external deployment proof

v0.6.0 completes the architectural move from a DTG-named fork to the neutral **RAHP Toolkit** and
turns the v0.5 portability claim into field evidence through a substantial external CAWG/C2PA
deployment.

## Highlights

- Renamed project/repository references to `sankarshanmukhopadhyay/rahp-toolkit` and updated the
  GitHub Pages base URL/JSON-LD identifiers for the neutral project identity.
- Added `profiles/cawg/rahp.yaml`, a 12-target branch-aware external profile spanning CAWG assertion
  specifications, published experiments/profile work, UX guidance and the C2PA specification.
- Added eight completed worked RAHP pressure tests under `examples/cawg-c2pa/`.
- Added `instances/cawg/` with durable observed-revision state and generated target manifest.
- Added portable `tools/instance_monitor.py` for material-change detection against any static RAHP profile, keyed by `repository@branch`; source monitors tolerate empty/uninitialised GitHub repositories (HTTP 409) as a tracked `no-commits` state while continuing to fail on genuine API/authentication errors.
- Added deduplicated GitHub assessment-issue publication through
  `tools/publish_assessment_issues.py`.
- Added `.github/workflows/instance-watch.yml` to monitor both DTG and CAWG/C2PA deployments,
  create `assessment-required` issues, and persist observed revisions.
- Preserved the DTG Portfolio Monitor adapter as an instance-specific discovery mechanism; CAWG
  does not inherit DTG portfolio metadata or governance state.
- Removed obsolete root-level release checklist/release-note duplicates; canonical release notes now
  live under `docs/releases/`.
- Completed a full active-documentation identity pass so RAHP Toolkit is consistently presented as the portable project, with DTG and CAWG/C2PA described as independently governed deployments.
- Added CI enforcement for the v0.6 project/deployment identity boundary.
- Hardened pressure-test validation so deployment-local risk vocabularies such as CAWG `CRK-*` resolve in clean CI checkouts.
- Updated validation workflows to current Node 24-based checkout/Python setup action generations.

## CAWG/C2PA assessment conclusion

The initial tests show a consistent mandate-readiness boundary: C2PA and CAWG provide increasingly
strong cryptographic and semantic evidence, but a relying party still needs explicit policy for
**authority, lifecycle, conflict resolution, required evidence, accessibility and historical
verification**. A single `valid` or `verified` UI/decision state is therefore not an adequate mandate
boundary across the portfolio.

Consent and Endorsement receive the strongest caution because authorization/delegation semantics and
lifecycle behaviour are still evolving. Identity, Metadata, Training/Data Mining and Organizational
Identity are technically stronger, but mandate profiles still need trust/governance policy around
them.

## Compatibility and authority

The YAML deployment profile remains the portability boundary. The DTG instance remains supported under
`instances/dtg/`; its corpus, risks, controls and governance records are not automatically loaded by
the CAWG/C2PA target profile.

The CAWG/C2PA assessment is independent. Upstream specification ownership and approval remain with
CAWG/DIF/C2PA.
