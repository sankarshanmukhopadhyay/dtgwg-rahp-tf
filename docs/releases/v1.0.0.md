# v1.0.0 — Stable Method and Implementation Conformance

v1.0.0 is the first stable RAHP Toolkit release. It does not declare the risk catalogue or any deployment permanently complete; it stabilizes the **portable contracts by which those things are assessed, implemented and evolved**.

## Stable boundary

- `rahp-engine-contract-v1` remains the engine contract.
- normalized result schema `version: 1` is stable.
- `rahp-evidence-retention-v1` remains the evidence lifecycle policy.
- published RAHP identifiers are not reused after retirement.
- breaking method changes require the next major toolkit release.

`method/versioning.yaml` records the compatibility rules explicitly.

## Implementation conformance

Python and TypeScript are independent reference implementations. v1 expands differential checks beyond result validity and retention planning to configured-target enumeration and trigger-correlation behavior. Neither implementation is normative; method YAML, schemas, policies and shared fixtures remain authoritative.

## Documentation information architecture

The rendered site is reorganized around reader goals: Learn, Adopt, Run assessments, Operate assurance, Implement, Deployments & examples, Reference and Releases. Deep deployment/register pages remain discoverable within their owning section without overwhelming the primary navigation. A validator now rejects unowned renderable documentation pages.

## Deployment evidence

DTG, CAWG/C2PA and A2A continue to demonstrate different portability shapes: multi-spec governance, content-authenticity composition/implementation assurance, and agentic/asynchronous protocol pressure testing. Their governance state remains independent of the portable method.

## Pre-tag rendering hardening

Before the v1.0 tag, the Pages deployment was inspected at the generated Jekyll-artifact level. Several deployment and durable-review Markdown sources had front matter but no layout, causing Jekyll to emit bare HTML fragments rather than full Just-the-Docs pages. v1.0 now requires an explicit layout for every front-matter Markdown page, validates the themed shell on canonical routes after Jekyll build, renders the A2A detailed assessment as a first-class Pages route, and quotes special-character Mermaid labels defensively.

## What v1 does not imply

A stable toolkit does not mean every upstream specification has a current assessment, that governance queues are closed, or that all reference packages must be published to a package registry. Current-state assessments and package publication remain explicit operational/release decisions.
