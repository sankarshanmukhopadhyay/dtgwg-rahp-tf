# v0.5.0 — Configuration-driven portable assessment

v0.5.0 changes the unit of RAHP adoption from an independently maintained copy of DTG instance data to a **schema-validated YAML deployment profile**.

## Highlights

- New `tools/rahp.py` CLI for configuration validation, target discovery, repository preparation, and review scaffolding.
- New `method/schema/rahp-config.schema.json` portability contract.
- One configuration may list a single repository or a portfolio of repositories, with target context and include/exclude scope.
- Each target can allow `rahp`, `security`, and/or `combined` review modes.
- Commit provenance can come from a pinned SHA, a local Git checkout, or remote branch resolution.
- `profiles/dtg/rahp.yaml` makes the current DTG use of RAHP an exemplar deployment rather than an engine dependency.
- Non-DTG examples demonstrate minimal, multi-repository, and security-only configurations.
- CI portability testing verifies that a synthetic non-DTG profile can exercise target discovery and all three review modes without DTG corpora, portfolio metadata, governance issues, or instance records.
- A generic configured-review GitHub Actions workflow removes hard-coded DTG target choices from the portable execution path.

## Compatibility

The existing `data/`, `corpora/`, worked reviews, validators, renderers, and generated evidence remain in place for the bundled DTG exemplar. v0.5 intentionally adds the neutral configuration layer without forcing a disruptive migration of proven DTG artefacts.

## Governance boundary

RAHP still does not infer defensible findings merely because a repository is configured. The tooling resolves targets, scaffolds records, validates structured evidence, and renders outputs. Human or AI-assisted reviewers remain accountable for substantive interpretation and findings.
