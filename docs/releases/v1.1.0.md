# RAHP Toolkit v1.1.0

Released: 2026-08-17

v1.1.0 introduces a **portable assurance knowledge model** above the stable v1 engine contract. It enriches RAHP from deployment-linked catalogues into reusable harm, risk, control, guardrail, assurance and evidence patterns while preserving deployment independence.

## Added

- `method/catalogue/` with 139 portable patterns: 24 harms, 38 risks, 31 controls, 12 guardrails, 19 assurance patterns and 15 evidence patterns.
- `method/schema/catalogue.schema.json` and `tools/validate_catalogue.py`.
- Portable pattern relationships for control function, enforcement boundary, authority, evidence, control side effects, applicability and assurance level.
- Eight additional scenario stress patterns for authority inference, delegation, discovery, redress, political economy, lifecycle composition and mitigation side effects.
- A dedicated Trust Tasks × DTG Credential Specification RAHP pressure-test exemplar and combined cross-lens composition review.
- Human-readable assurance knowledge-model and catalogue reference documentation.
- Generated `build/portable-assurance.json` and `build/derived/portable-catalogue-coverage.json` machine-readable release artefacts.

## Changed

- All curated RAHP and security examples are revalidated against v1.1.0 and carry `portable_assurance` mappings in addition to deployment-specific risk/control references.
- The composed Trust Tasks × Credential Specification corpus now maps each `XSP-*` scenario to reusable portable assurance patterns.
- Pressure-test and security renderers expose portable pattern mappings in generated Markdown.
- Validators require portable assurance mappings for curated v1.1 examples and validate all references.
- Release, roadmap, README, adoption and assessment documentation now explain the method/deployment/catalogue boundary.

## Compatibility

`rahp-engine-contract-v1`, normalized result schema version `1` and `rahp-evidence-retention-v1` remain stable. The v1.1 catalogue is an additive method capability and does not require a v2 engine contract.

## Validation

The release is expected to pass the repository's Python validation/build suite, scenario and review validators, documentation checks and TypeScript conformance checks. `tools/validate_catalogue.py` intentionally reports non-failing catalogue-quality warnings where a high-agency portable risk has controls but no dedicated portable guardrail yet; these remain visible as future enrichment work.


## Post-release HEAD qualification — 2026-08-17

The full maintained example estate was qualified against current default-branch HEADs. Eight of eleven live repositories were unchanged, A2A had only a non-material documentation-link change, Credential Spec resolved the optional-VWC-digest security finding, and Trust Tasks materially strengthened replay, authorization, authority re-evaluation, task control, proof profiles, citation integrity and payload validation. See [v1.1 HEAD qualification](../head-qualification.md).


## Structured-data Pages routing

The v1.1 documentation surface preserves canonical structured files at their existing `.yaml`, `.json` and `.jsonld` paths and renders human-readable Just-the-Docs projections on clean sibling routes. For example, `corpora/trust-tasks.yaml` remains machine-readable while `/corpora/trust-tasks/` is the reader view. The same contract applies to the portable catalogue under `/method/catalogue/`, with `/method/catalog/` retained as a compatibility index. CI validates that neither surface can silently replace the other.

## Generated assurance-site refresh

The generated `build/site/` publication surface now reflects the v1.1 repository architecture. `portable-catalogue.html` renders the reusable `HRM/RKP/CTP/GRP/ATP/EVP` layer, and `assurance-graph.html` exposes machine-derived catalogue coverage plus the current HEAD qualification evidence. Existing generated risk, catalogue, normative, matrix, lifecycle, governance, assurance and Task Force pages are explicitly labelled as DTG deployment views. Historical `catalogue.html#RK-*` anchors are preserved for evidence-link compatibility.
