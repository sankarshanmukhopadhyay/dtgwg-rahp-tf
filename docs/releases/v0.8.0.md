# v0.8.0 — Engine Boundary

v0.8 turns the execution lifecycle established in v0.7.1 into a language-neutral
contract. It deliberately stops short of a TypeScript rewrite: the purpose of this
release is to make a future TypeScript or Rust implementation conform to RAHP rather
than redefine it.

## Added

- `method/engine-contract.yaml` with the portable execution lifecycle and operation boundary.
- normalized `rahp-result` JSON Schema.
- implementation-neutral engine conformance fixtures.
- `tools/engine_contract.py` reference adapter and engine-contract validator.
- explicit evidence-retention classes and deployment-configurable retention defaults.
- ignored `.rahp/` run workspace and explicit promotion of curated worked examples.

## Execution model

```text
source → observation → trigger → assessment → finding → disposition → baseline
```

The contract preserves the v0.7.1 distinction between source events and assessment
work items and makes normalized results suitable for a future SDK/API.

## Storage decision

v0.8 rejects the model where every run becomes permanent repository history. Raw
logs, cloned targets, intermediate renders and draft reviews are ephemeral. Compact
assessment/disposition records remain durable. Large supporting evidence is normally
kept outside Git and referenced by immutable URI plus SHA-256.

This keeps the repository reviewable while preserving assurance traceability.

## Curated review revalidation

Before the release archive is cut, all committed RAHP pressure-test and security-review exemplars are revalidated with the v0.8 validators/renderers and their `reviewed_against` metadata records `rahp-engine-contract-v1`. This is a **method/engine revalidation of the pinned review records**, not an assertion that the upstream target repositories were re-reviewed at newer commits. Target pins and original review dates remain unchanged.

## Compatibility

Existing curated examples remain in `examples/`, and existing instance review records
remain valid. New review initialization defaults to `.rahp/reviews/`; use explicit
promotion when a run should become a maintained example.

## Next

v0.9 can now implement a TypeScript reference SDK against a stable boundary: generated
types from normative schemas, graph traversal, programmatic assessment APIs and CLI
integration without treating Python internals as normative.
